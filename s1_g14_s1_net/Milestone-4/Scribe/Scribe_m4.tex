% ---------------- SCRIBE QUESTION 1 ----------------
\item \textbf{Baseline System and Motivation for Randomization}

\subquestion{What was the deterministic baseline?}

In Milestone 3, we built a simulation of a drone cellular network where UAVs act as flying base
stations serving a single stationary user on the ground. The drones' starting positions were placed
using a Poisson Point Process at a fixed density, and each drone then travels in a straight line at a
random angle.

The system always connects the user to whatever drone happens to be physically closest at that
moment --- this is the nearest-neighbor association policy:
\[
x^*(t) = \arg\min_i \|x_i(t)\|
\]
A handover gets recorded every time the identity of that closest drone changes. We looked at two
movement scenarios: SSM, where every drone flies at the same fixed speed, and DSM, where each
drone is assigned its own speed sampled from either a Rayleigh or Uniform distribution. Every
parameter in M3 was held constant, matching the values confirmed in the paper and slides:

\vspace{0.3cm}
\begin{center}
\begin{tabular}{ll}
    \toprule
    \textbf{Parameter} & \textbf{M3 Fixed Value} \\
    \midrule
    Drone density $\lambda_0$ & $1.0$ DBS/km$^2$ $= 1 \times 10^{-6}$ /m$^2$ \\
    Speed (SSM) & $45$ km/h ($12.5$ m/s) \\
    Exclusion radius $u_0$ & $500$ m \\
    Time window $T$ & $400$ s \\
    Monte Carlo runs & $1{,}00{,}000$ simulations \\
    \bottomrule
\end{tabular}
\end{center}
\vspace{0.3cm}

\subquestion{Why introduce randomization?}

Running everything at one fixed set of values only tells us the theory holds for that single scenario.
In practice, drone networks look different every time they're deployed --- the number of drones, their
speeds, and the distances involved all vary. When we instead draw parameters randomly each run,
every simulation becomes its own independent test. If the theoretical predictions still hold up across
all of those varied runs, we can be confident the results genuinely generalize rather than being a
coincidence of one carefully chosen configuration.

\subquestion{What component now involves randomness?}

We built a new central module called \textbf{randomised\_config.py} that executes at the very
beginning of each simulation. Rather than loading hard-coded constants, it samples five key physical
parameters fresh from Uniform distributions every run. Everything else --- the nearest-neighbor
connection rule, the handover detection logic, and how the drones move --- stays exactly the same

\item \textbf{Probabilistic Reasoning Behind the Algorithm}

\subquestion{How does randomness help address uncertainty?}

In a real-world drone network, nothing stays fixed --- drone counts, speeds, and deployment distances
all shift from one situation to the next. If we only ever test at one specific configuration, the most we
can conclude is that the theory works there. By sampling parameters from distributions, each run
probes the theory at a completely different operating point. Agreement across all of those varied
conditions is a much stronger form of validation.

\subquestion{What probabilistic models support this design?}

\begin{itemize}[leftmargin=*, itemsep=0.3em]
    \item \textbf{PPP for drone deployment:} The paper's derivations hold for any density $\lambda_0$,
          so randomizing it simply tests the same theory at a different point rather than violating
          any assumption.

    \item \textbf{Displacement Theorem (Lemma 1):} This result guarantees that drones remain
          Poisson-distributed at every instant regardless of how they move, for any $\lambda_0$ ---
          our randomized value still falls within that guarantee.

    \item \textbf{Speed PDF for DSM (Lemma 3):} Lemma 3 applies to any valid speed distribution
          $f_v(v)$, so choosing a different Rayleigh sigma $\sigma$ just plugs a different valid
          distribution into the same formula without breaking anything.

    \item \textbf{Exclusion radius $u_0$:} Varying $u_0$ across the $300$--$800$ m range captures
          the reality that drones don't always land at the same distance from a user.
\end{itemize}

\subquestion{Why is this expected to improve the analysis?}

The randomized approach doesn't change the underlying handover physics. What it does is make our
conclusions far more defensible. A finding that holds across many independently drawn parameter
settings is substantially more convincing than one that was only ever verified at a single
hand-picked configuration.

\item \textbf{Implementation Within the Simulation Pipeline}

\subquestion{What changes were made to the code?}

The only new file created in this instance of the code is \texttt{randomised\_config.py}. It has three
functions: \texttt{sample\_params()}, which randomizes and gets all five parameter values;
\texttt{save\_params()}, which saves the five parameters to a JSON file; and \texttt{load\_params()},
which loads the five parameters back from the JSON file. All simulation and theory scripts call
\texttt{load\_params()} so that they will all use the same sampling of parameters.

The updated pipeline is as follows:

\begin{itemize}[leftmargin=*, itemsep=0.3em]
    \item \textbf{Step 1:} Call \texttt{sample\_params()} in the \texttt{handover\_dbs\_simulation.py}
          script. Samples the five parameters, drawn from their distributions.

    \item \textbf{Step 2:} Displays the five parameters just sampled. All those parameters are saved
          in \texttt{Data/handover\_run\_params.json}.

    \item \textbf{Step 3:} $10{,}000$ Monte Carlo simulations are run using the sampled values for
          $\lambda_0$, $V_{\min}$, $V_{\max}$, and $T$; where the parameter $\lambda_0$ is sampled
          using random values.

    \item \textbf{Step 4:} All theory scripts that simulate constant velocity, the Rayleigh lower bound
          and the Uniform lower bound will call \texttt{load\_params()} and retrieve their parameters
          using the same JSON file.

    \item \textbf{Step 5:} The script \texttt{plot\_handover.py} loads all the result \texttt{.npy}
          files and generates the final comparative plot.
\end{itemize}

\subquestion{How is randomness generated inside each realization?}

\begin{itemize}[leftmargin=*, itemsep=0.3em]
    \item Number of drones: $N \sim \text{Poisson}(\lambda_0 \times \pi \times R^2)$, $R = 30$ km.
    \item Starting positions: $r = R \times \sqrt{U}$, $U \sim \text{Uniform}(0,1)$;
          angle $\theta \sim \text{Uniform}(0, 2\pi)$.
    \item Movement direction: $\varphi \sim \text{Uniform}(0, 2\pi)$ per drone.
    \item DSM speeds: $v \sim \text{Uniform}(0,\ 107.5\ \text{km/h})$ per drone for this run.
    \item SSM speed: all drones share the same constant $v_{\text{Mean}} = 53.1$ km/h for this run.
\end{itemize}

\subquestion{Does everything else in the pipeline remain unchanged?}

Yes, all other aspects regarding the nearest-neighbor decision process, how to detect when a user is
handed over, how to keep a drone moving straight, and the Monte Carlo loop remain unchanged from
M3 with regard to their mechanics; however, instead of being hard-coded, the 5 input parameters
will now be randomly drawn from the input generation distribution.

\item \textbf{Evaluation Metrics and Comparative Results}

\subquestion{Why are these metrics appropriate for this problem domain?}

We used 4 metrics that connect to each other in order to gauge if the randomized DSM is superior to
the deterministic SSM system. Both M3 and M4, which evaluate the two systems, utilize the same
nearest-neighbour rule as well as the same simulation process; only the set of parameters would
differ between M3 and M4.

The four metrics we created are:
\begin{enumerate}[leftmargin=*, itemsep=0.2em]

\subquestion{Metric 1: Handover Probability $P[H(t)]$ --- Foundational Domain-Specific Measure}

\textbf{What it is:} The likelihood that a ground user will have had to switch to a different drone
connection at least once by time $t$. This is the primary metric for the project as a whole and is
based upon Theorem 2 (SSM) and Theorem 3 (DSM) as defined in the Theoretical Paper.

\textbf{Why it is appropriate:} Handover Probability is a direct measure of the stability of the
connection between a user and the drone cellular network. All other metrics that have been defined
will be based upon this metric. A lower $P[H(t)]$ will necessarily be better than a higher $P[H(t)]$,
since it indicates that a user has maintained their original connection to their drone longer than
alternative connections.

\textbf{From the M3 Handover Simulation (Deterministic, 100,000 simulations):} From the results
obtained from running the simulation with 100,000 runs, the 3 deterministic curves (Rayleigh,
Constant, and Uniform 40) have a common characteristic in that they increase steeply from 0. The
simulation points from the 100,000 runs fall on top of the theoretical traces for all of the curves from
0 through 300 m/s. Constant speed and Uniform 40 had both reached a value of $P[H] \approx 0.97$
by $u_x = 150$ m. Rayleigh lagged well behind, achieving its approximate maximum
(i.e.\ $\approx 1.0$) by $u_x = 300$ m. These two measures demonstrate that there is an extremely
close correspondence between the Theoretical and Simulation results at the same fixed deterministic
variables.

\highlight{Regarding the transfer of probability from the M4 graph (Randomized, SSM vs DSM) in
terms of time $t$: From the M4 graph above, the x-axis is a function of time ($t$). SSM and DSM both
start at approximately 0.05 at $t=0$ and remain similarly close until approximately 40 s. At this point,
however, SSM increases rapidly compared to DSM which continues to develop slowly. In addition,
the Mean Squared Error (MSE) between the simulated and theoretical lower bound to that of DSM is
only $6.2 \times 10^{-6}$ which indicates that the theory remains valid under both initialized
iterations.}

\subquestion{Metric 2: Expected Communication Cost --- Resource Utilization Metric}

\textbf{What This Is:} In a cellular drone network, whenever a user hands over from one drone to
another, control signals (i.e., messages for authenticating the user, requesting resource allocations,
and transferring sessions, also known as signaling overhead) have to be exchanged between the user,
old drone, and new drone before the handover can take place. Therefore, Handover Probability can
serve as a direct representation of this cost (i.e., the lower $P[H(t)]$, the lower the overhead of
signaling and the greater the total amount of bandwidth available for actual user data).

\textbf{Why This Is Appropriate:} As indicated on the M4 rubric, the utilization of all resources
(e.g., network) is a valid metric. In a cellular drone network, control signals (e.g., signaling overhead)
use bandwidth that could otherwise be used for user data. Therefore, a strategy that reduces
handovers will have a more resource-efficient environment.

\textbf{How We Measure This:} The communication cost savings will be defined as a ratio of the
number of users that do not trigger signaling for a handover in a DSM compared to an SSM:
\[
\text{Cost Saving}(t) = P_{\text{SSM}}(t) - P_{\text{DSM}}(t)
\]

\text{Expected Latency}(t) = P[H(t)] \times 40\ \text{ms}

\textbf{Why it is appropriate:} \highlight{The reason this is valid is because latency is defined in

control of drones, and/or streaming from sensors. Therefore even 40 ms of service interruption in
between two connections is significant enough to warrant a reduction in total service interruption by

\subquestion{Metric 4: Connection Stability $CS(t) = 1 - P[H(t)]$ --- Stability Metric}

\textbf{What it is:} Connection Stability is defined as the percentage of users that have not
experienced a handover (switchover) at time $t$, calculated by the formula:
$\text{Connection Stability} = 1 - \text{Handover Rate (Probability)}$.
Higher values of Connection Stability indicate that more users are still on their original and
uninterrupted connections.

\textbf{Why it is appropriate:} \highlight{This measure converts Handover Rate (Probability) into
something that is of direct interest to network operators: how many users in their network are
currently using a stable connection? Thus allowing comparison of SSM (Single Site Management)
with DSM (Dynamic Subscriber Management) easily and intuitively.}

\subquestion{Interpretation: Why Does the Randomized DSM Perform Better?}

In the SSM, all the drones are moving at one speed and have the same distance to their destination
which causes all of them to drift together. Also, when another drone comes close enough to a user,
they will take over the connection to that user which will require a hand-over. Hence users cannot be
protected from any variation in the connections to the drones.

In the DSM, each drone has been assigned a different speed from a continuous distribution and thus
some drones will be travelling quickly while drifting away, and some will be travelling slower and
remaining near their starting position. The user will always connect to the drone closest to him;
therefore any drone that has randomly drawn a slow speed becomes a natural anchor as it remains
closest to the user longer than any of the faster drones could possibly pass it. Therefore, this
controlled randomness in the speed of the drones creates a natural stabilization to the location of
the people and, thus the DSM has a much larger delay for handovers than the SSM.

The proof of that property is encapsulated in Theorem 3 of the paper, and shows that the probability
of a handover in the DSM is always less than that of the SSM as time approaches infinity. The results
of both the SSM and DSM under the deterministic known parameters of M3 and the random
parameters of M4 demonstrate this result is both strong and general.

\item \textbf{Insights and Remaining Challenges}

\subquestion{What did we learn from this experiment?}

\begin{itemize}[leftmargin=*, itemsep=0.4em]
    \item \textbf{The theory works for randomized parameters too.} The theory had been validated
          only with the paper's predetermined values in M3 and then again in M4 through the MSE
          between the DSM simulation and the theoretical lower bound through a completely different
          set of parameters to give an MSE of only $6.2 \times 10^{-6}$. This proves the generality
          and robustness of the paper's formulas.

    \item \textbf{Higher drone density speeds up handovers.} M4 drew $\lambda_0 = 1.44$/km$^2$
          vs M3's $1.0$/km$^2$. This alone moved $t_{50\%}$ from 38 s to 25 s for SSM. More drones
          eligible for one of them as the closest drone means that handovers can occur earlier and
          this is shown in M2 as well. The more density of drones available, the more likely it is that
          you will be switching drones.

    \item \textbf{DSM performs better on all four metrics.} Lower probability of having a handover,
          less communication costs, lower cumulative latencies and better connection stability some
          $t > 40$ s. If the user requires a stable connection for extended periods of time, then using
          variable-speed drones proves to be a better alternative.

    \item \textbf{Both models behave similarly at early times.} Both the models behaved similarly
          in the short time span ($t < 40$ s). The M3 and M4 graphs show that the SSM and DSM
          curves begin pretty much close together, but it is not until about $t \approx 40$ seconds
          that the curves significantly diverge. The advantage to the model selection for very short
          lengths of time does not have much bearing on the total time a user will be using a
          variable-speed model or a fixed-speed model.
\end{itemize}

\subquestion{When does the randomized method exceed or fall short of expectation?}

\begin{itemize}[leftmargin=*, itemsep=0.4em]
    \item The benefit of the randomized algorithm is that it examines the theory for many different
          input parameter settings and establishes that the conclusions are not restricted to a single
          input parameter setting, which could never be shown using only the deterministic baseline.

    \item The disadvantage of the randomized method is that it creates a higher degree of noise
          through fewer iterations; Using $1{,}000{,}000$ iterations in the M3 simulation provided
          handover coordinate values that matched almost perfectly with theoretical values. The M4
          simulation, which only used $10{,}000$ iterations, added a greater variance to the handover
          coordinate values; Still, the agreement was reasonable overall.

    \item One remaining limitation is that the simulation uses a circular area with a radius of 30 km,
          whereas the mathematical model assumes an infinite plane. Drones that wander outside of
          the predetermined limits decrease the effective density as time increases, creating a small
          mismatch between the theoretical and simulated values that cannot be accounted for
          mathematically.

    \item A second limitation is that the lower bound for the DSM algorithm becomes looser as it
          becomes larger (i.e., time). The dotted purple Rayleigh lower bound from the M4 Handover
          Probability graph falls below the DSM simulation curve for large $t$. This lower bound was
          based on neglecting the time correlation of drone positions. Finding a tighter lower bound
          as $t$ increases remains an open issue in this paper.
\end{itemize}

\end{enumerate}
